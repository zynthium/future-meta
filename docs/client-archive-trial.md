# 客户端下载格式试验

本试验只优化终端下载的 `.fmeta.zst`，不修改维护库。获选的按合约变更序列方案已接入 0.5.0 正式编解码器，见 [格式迁移说明](archive-format.md)。本文和 example 保留原始试验方法；正式版本以 Git tag `v0.5.0` 和线上 manifest 为准。

## 复现

```sh
cargo run --release -p future-meta --example archive_storage_trial -- \
  data/storage-trial-final-20261019/baseline-public/latest.fmeta.zst \
  data/client-archive-new
```

输出目录必须不存在。程序生成各候选的 `*.trial.zst` 和 `comparison.json`，不会写 `public/`。

## 候选

- `schema3`：当前模型、bincode、zstd 等级 19。
- `schema3_zstd22`：只提高 zstd 压缩等级，保持当前 schema 3 和原始序列化字节，现有客户端可读取。
- `dictionary`：共享手续费载荷、多空保证金组合、交易规格、状态及原始日期文本。每条联合参数记录只保存字典引用。
- `contract_changes`：在字典基础上按合约批量保存变更，日期引用使用增量编码；结束日期在确实等于下一条起点时省略，真实空档使用显式覆盖保留。
- `split`：手续费、保证金和状态分别合并自身未变的相邻区间，解码时按边界并集还原联合版本。
- `shared_members`：对同品种内相同的完整区间分组，显式保存合约成员，再还原每个成员的独立记录。编码不保存可由 symbol 派生的品种代码，也不把其他合约或日期加入适用范围。

后四种使用独立试验标记 4294967294；历史原型文件曾使用标记 4，但与最终正式 schema 4 布局不同，只能由该试验 example 读取，不能作为正式 artifact 分发。正式 0.5.0 编解码器使用 `compact_archive.rs` 中定义的格式。

## 不变的语义

所有候选均还原当前 `FeeArchiveV3`，逐字段比较，并核对全部 bincode 序列化字节。保留合约 ID、symbol、上市/到期日期、当前规格、所有规格区间、规则哈希、四项手续费、多空保证金、未知值、状态和原始时间文本；没有删历史、推测费率或按众数补值。

解码后继续使用当前 `FutureMeta` 索引和查询实现。每个候选执行 1,000 个实际 as-of 查询并与原始版本比较。加载计时包括解压、解码、还原和索引构建；查询计时使用同样的 API、已解析时间、1000个样本重复100轮，报告舍弃首轮后7次中位数折算值。

各候选还原相同的拥有所有权的数据模型，因此本次不声称减少常驻对象内存。压缩前序列化体积不是 Rust 堆内存或 RSS。若以后优化常驻内存，需要单独设计共享载荷索引，并保持公开查询语义。

## 采用前

0.5.0 已增加有边界检查的正式解码路径，并继续支持 schema 1/2/3；生产端切换必须在客户端升级后进行。终端按 symbol/as-of 查询的 API 可以保持不变。若只采用 zstd 等级调整，则不需要协议迁移。

实测数值见 `data/client-archive-final-20261019/RESULT.md`。维护库存储试验的结果不代表客户端下载文件的收益。
